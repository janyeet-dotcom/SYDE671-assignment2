Part One: Fun with Filters

1.1 Convolution from Scratch

Images are represented by matrices of pixel values, and image filters can be represented as smaller matrices. To apply the filter, we can slide the filter kernel over every pixel, multiply th weights, and sum the outcome into one output pixel. This is called convolution, and it is a fundamental operation in image processing and computer vision.

Here, I've started with building my own convolution function in Python. Using four loops will go over every image pixel and every kernel entry. Two loops will go over the image pixels, and two loops will go over the image pixels and use NumPy to do the multiplication and summing. They will give the same output, but the second one will be faster. I've attached the code and the outputs of these operations below. 


def convolve2d_four_loops(image: np.ndarray, kernel: np.ndarray) -> np.ndarray:
    """Convolution with four explicit for loops (image rows/cols, kernel rows/cols)."""
    image = np.asarray(image, dtype=np.float64)
    kernel = np.asarray(kernel, dtype=np.float64)
    h, w = image.shape
    kh, kw = kernel.shape

    padded = pad_zeros(image, kernel.shape)
    flipped = kernel[::-1, ::-1]  # flip both axes: true convolution

    output = np.zeros((h, w), dtype=np.float64)
    for r in range(h):
        for c in range(w):
            total = 0.0
            for i in range(kh):
                for j in range(kw):
                    total += padded[r + i, c + j] * flipped[i, j]
            output[r, c] = total
    return output

def convolve2d_two_loops(image: np.ndarray, kernel: np.ndarray) -> np.ndarray:
    """Convolution with two explicit for loops; the kernel sum is done with NumPy."""
    image = np.asarray(image, dtype=np.float64)
    kernel = np.asarray(kernel, dtype=np.float64)
    h, w = image.shape
    kh, kw = kernel.shape

    padded = pad_zeros(image, kernel.shape)
    flipped = kernel[::-1, ::-1]

    output = np.zeros((h, w), dtype=np.float64)
    for r in range(h):
        for c in range(w):
            output[r, c] = np.sum(padded[r:r + kh, c:c + kw] * flipped)
    return output

1.2 Finite Difference Operators

Mathematically, a derivative will calculate how fast something is changing, so an image derivative will highlight regions of rapid intensity change, which are edges. In two dimensions, we can take derivatives in x and in y, giving us Ix and Iy. However, we know conceptually that edges are not necessarily exclusively present in a single direction, so there is value in acquiring the gradient magnitude, which will tell us how strong edges are regardless of direction.

We can have a python script calculate these gradients, then threshold them so that magnitide of a certain strength can be classified as an edge. This threshold is going to be image depedent, a threshold too low will hold noise, while too high will delete the true edges. Using this cameraman image, I have calculated the gradients and applied different thresholds to see how the edges are affected. The results are shown below. The left image is showing the gradient magnitude map of the cameraman image thresholded at various levels. The right images is me having selected 0.3 as the best thresholding level, and showing the original image, the x and y derivatives, the gradient magnitude, and the thresholded edges.

1.3 Derivative of Gaussian (DoG) Filter

If you squint a little at the 0.3 threshold image, you might have noticed that there is still some noise that is captured in the manitude gradient thresholdng. A way to tackle this problem is to smooth the image before calculating the gradients. A common way to do this is to use a Gaussian filter, which will blur the image.

In this case, we used a Gaussian filter compared to the box filter from Part 1.1. It's kind of hard to compare a photo of me to the cameraman, so I've displayed the original image, the box filter, and the Gaussian filter below. We can see that the box filter provides a more uniform blur while the Gaussian does a better job a preserving the original features. This is because the Gaussian filter takes a weighted sum of the pixels nearby based on their distance from the pixel in question, so edges (which will likely span multiple pixels) will be preserved better than noise, which might be only affect a single pixel at a time.

We can see that because the Gaussian helps us reduce some of the noise at an earlier stage, we can use a lower threshold from the gradient map, while before we had to use a higher threshold to avoid capturing noise. Now, we can see the horizon line in the cameraman image clearly compared to before.

Turns out we can try to simplify the process by combining the Gaussian filtering and the gradient calculation into a single convolution. Convolutions are associative, so convolving the image with a Gaussian filter and then convolving the result with a derivative filter is equivalent to convolving the image with a single filter that is the convolution of the Gaussian and derivative filters. This is called a Derivative of Gaussian (DoG) filter, and it can be used to calculate gradients while also smoothing the image. We'll try to make sure this is the case! The results are shown below.

Part Two: Fun with Frequencies

2.1 Image "Sharpening"

Since we know that edges tend to be higher frequency components in the image, we can artificially "sharpen" an image by isolating the high frequency components and adding them back to the original image. This is called unsharp masking. To be able to program this in an intuitive way, the sharpening effect can be expressed by this equation: sharp = I + alpha * (I - I * G) G is the Gaussian, and we can control it's affect on the image by changing the σ-value. α is a scaling factor we can use to adjust the strength of the sharpening effect. I've shown the Taj Mahal image below with different σ and α values to see how the sharpening effect is affected.

In the Taj Mahal image, the edges of interest would be the marble inlay, the arch details, scaffolding and tree outlines. These are removed with the Gaussian blur, so we're seeing if they're added back with the unsharp mask. We can see that α = 0 to α = 1 gives us a subtle sharpening effect, while higher values of α result in a haloing effect, and even higher values can lead to over-sharpening and noise amplification. I selected α = 1.5 to be a good value to proceed, as we can see the finer details such as the dome texture and scaffolding are recovered without introducing too much noise or haloing. Now, we can see how the σ value affects the sharpening effect.

We can see that σ = 2.0 more severely blurs the original image, so the unsharp masking does a worse job at recovering the lost information because more of the high-frequency details are lost in the blurring process.
